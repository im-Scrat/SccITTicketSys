### Why one migration for three tables

`work_support_requests`, its items and its attachments are one entity family with
one lifetime: the children are meaningless without the parent, both cascade from
it, and `down()` drops them in reverse in a single reversible step. This follows
the `create_maintenance_tables` shape rather than the one-concern-per-migration
shape used for column additions. M1 is a genuinely separate concern (QR scan
identity) and is therefore a separate migration.

## 3. Schema as built

### 3.1 `qr_scan_logs` (additive)

```
ADD uuid       uuid NOT NULL DEFAULT gen_random_uuid()   -- backfilled, then made NOT NULL
ADD user_agent text NULL
ADD UNIQUE INDEX qr_scan_logs_uuid_unique (uuid)
ADD INDEX qr_scan_logs_code_scanned_index (qr_code_id, scanned_at)
```

The migration adds the column nullable, backfills with
`UPDATE ... SET uuid = gen_random_uuid() WHERE uuid IS NULL`, and only then sets
the default and `NOT NULL`. Both stacks are empty today, but a migration that
only works on an empty table is a migration that fails the first time it matters.

`maintenance_record_id` — the DD-50 join for proof of work — already existed in
the baseline and needed no change. Its single-FK cardinality is what makes
"one scan binds at most one maintenance record" structural rather than
procedural; a test asserts the column shape so Stage E can rely on it.

### 3.2 `work_support_requests`

Public `uuid`; required `pc_unit_id` (RESTRICT); nullable `ticket_id` and
`maintenance_record_id` (SET NULL); required `technician_id` (RESTRICT);
`explanation`; six-state `status`; decision metadata (`decided_by` SET NULL,
`decided_at`); `decline_reason`; `rescheduled_to` / `reschedule_reason` /
`acknowledged_at`; `clarification_reason` / `proposed_meeting_at`;
`cancelled_by` / `cancelled_at` / `cancellation_note`; `closed_at`;
`procurement_request_id` (SET NULL); `timestampsTz`.

**No soft delete**, deliberately: `cancelled` is the withdrawal path FR-WSR-014
specifies, and no FR-WSR describes archiving a request. A `deleted_at` nobody
sets is a column that invites a second, unaudited way to make a request
disappear.

**No `request_number`, no cost estimate** — those belong to purchasing (DD-51).

Indexes: `(technician_id, status)` for the technician's tracking page,
`(status, created_at)` for the administrator inbox, plus single-column indexes on
every foreign key.

### 3.3 `work_support_request_items`

`hardware_model_id` (SET NULL) **or** free-text `description`; `quantity`;
`remarks`. Cascades from the request.

### 3.4 `work_support_request_attachments`

Shaped after `asset_attachments` rather than invented: the same four security
columns (`original_filename`, `mime_type`, `file_size`, `checksum`), the same
private-disk `storage_path` that is never a public URL, and the same
`kind` split for display. No target CHECK, because unlike `asset_attachments`
and `qr_codes` it has exactly one possible owner.

Per OD-3 this will be served by `AttachmentSecurity::PROFILE_MAINTENANCE` — no
fourth profile, no second upload path (DD-45/DD-53). A test asserts the four
security columns exist, because a table that cannot record them cannot sit behind
that boundary.

### 3.5 The nine CHECK constraints, as verified in `pg_constraint`

| Constraint | Definition |
|---|---|
| `work_support_requests_status_check` | six controlled values |
| `work_support_requests_explanation_check` | `explanation !~ '^[[:space:]]*$'` |
| `work_support_requests_decline_reason_check` | `status <> 'declined' OR (decline_reason IS NOT NULL AND decline_reason !~ '^[[:space:]]*$')` |
| `work_support_requests_decided_at_check` | `status NOT IN ('approved','declined') OR decided_at IS NOT NULL` |
| `work_support_requests_cancelled_at_check` | `status <> 'cancelled' OR cancelled_at IS NOT NULL` |
| `work_support_request_items_quantity_check` | `quantity > 0` |

| `work_support_request_attachments_kind_check` | `kind IN ('image','document')` |
| `work_support_request_attachments_file_size_check` | `file_size IS NULL OR file_size >= 0` |

## 4. Two defects the tests caught

Both were found by the test suite before any further code was built on the
schema. Both are recorded in project memory.

### 4.1 `btrim()` trims spaces only — the database was refusing a different set than the application

The first draft used `CHECK (btrim(explanation) <> '')`. Postgres `btrim` with no
character argument strips **spaces only**, so an explanation of `"\t\n"` passed
the database while PHP's `trim()` — which also strips tabs, newlines, carriage
returns, vertical tabs and NULs — rejected it one layer up.

That makes DR-020's *"refused at the database level **as well as** the
application level"* decorative: the two layers would refuse different sets of
values, and the database layer would be the weaker one.

**Fixed** by replacing every text-emptiness CHECK with the POSIX blank test
`!~ '^[[:space:]]*$'`, which matches what PHP `trim()` rejects. The test datasets
now include `''`, `'   '`, `"\t"`, `"\n"`, `"\r\n"`, `"\t\n "` and
`"  \t  \r\n  "`.

### 4.2 A CHECK naming an `ON DELETE SET NULL` column blocks the cascade

The approved constraint text was
`CHECK (status NOT IN ('approved','declined') OR (decided_by IS NOT NULL AND decided_at IS NOT NULL))`.

Deleting the deciding administrator issues an UPDATE against every request they
decided (via `ON DELETE SET NULL`), and that UPDATE **re-evaluates every CHECK on
the row**. Naming `decided_by` would therefore turn a routine account purge into
a constraint violation — and the tempting "fix" would have been to weaken the
audit rather than the constraint.

**Implemented as `decided_at IS NOT NULL` only.** Same invariant (a decision
carries the moment it was made), no coupling to a nullable actor FK. The
deciding actor is still stored in `decided_by` and durably recorded in
`activity_logs` per FR-WSR-011.

There is a dedicated test — *"it survives deletion of the deciding
administrator"* — that hard-deletes the decider and asserts the request survives
with `decided_by` nulled and its status intact.

**This is the one deviation from the approved §22 schema, and it is reported
rather than silently applied.**

## 5. Test defect corrected

One test had to be split. A failed statement aborts the enclosing Postgres
transaction (`SQLSTATE 25P02`), and `RefreshDatabase` wraps each Pest test in
exactly one. A test that asserted a rejection and then performed a valid insert
was not testing two rules — it was testing one rule and reporting the poisoned
transaction as a bogus second failure.

*"it requires a pc unit and protects it from deletion"* became two tests:
*"it requires a pc unit"* and *"it protects the pc unit from deletion while a
request references it"*.

### Test coverage in `WorkSupportSchemaTest` (40 tests)

`qr_scan_logs`: uuid generated by the database · uuid uniqueness · single-FK
cardinality for `maintenance_record_id` · the composite index exists · the scan
log survives deletion of its QR code.

`work_support_requests`: a well-formed request is accepted · blank explanation
refused (7 blank variants) · status outside the six refused · decline without a
reason refused (5 variants) · decline with a reason accepted · decision without
`decided_at` refused · cancellation without `cancelled_at` refused · **survives
deletion of the deciding administrator** · pc unit required · pc unit protected
from deletion · ticket and maintenance context optional.

Items: non-positive quantity refused (0, −1) · item naming nothing refused
(5 variants) · free-text item accepted.

Attachments: kind outside the split refused · negative file size refused · the
four attachment-security columns present.

Cascades: items and attachments deleted with the request.

Boundary: `procurement_requests` still carries no `pc_unit_id`, `ticket_id` or
`maintenance_record_id`, and its status CHECK still contains no
`clarification_requested`.

**These tests speak SQL, not Eloquent, on purpose.** Where a requirement says a
rule is enforced at the database level, a test that goes through a model which
also validates proves nothing about the database. Every negative case asserts on
the **constraint name**, so a test cannot pass because some other rule happened
to reject the row.
