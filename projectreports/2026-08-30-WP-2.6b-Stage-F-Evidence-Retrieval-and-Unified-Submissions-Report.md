```

GET /api/technician/submissions
```

Both behind `auth:sanctum → active → AuthenticateSession → password.current →

**There is no `GET /attachments/{uuid}`,** and a test asserts its absence along
with the other flat shape someone might reach for.

## 3. Authorization

### Evidence download — the sequence, in order

```
authenticated actor
→ can:maintenance.view                       (route floor)
→ authorize('view', $workSupportRequest)     → WorkSupportVisibility::canSee()
→ attachment belongs to that request         (route scoping + an explicit guard)
→ file exists on the private disk
→ AttachmentSecurity::stream(..., PROFILE_MAINTENANCE)
```

**No new ability and no new permission.** Reading the evidence is part of reading
the request, so the existing `view` ability is the boundary — a technician
reaches their own, an administrator reaches any, and nobody gained anything they
did not already have.

`->scopeBindings()` was added deliberately rather than relying on Laravel's
implicit child scoping: the non-disclosure property should be a property of the
route, not of a framework convention that a future refactor might not preserve.
The controller's explicit parent-key check remains as defence in depth.

### The unified feed

`GET /technician/submissions` takes **no identifier at all** — no `{user}`, no
`technician_id` filter. The subject is the session, so "someone else's
submissions" is not a request this endpoint can express. That is a stronger
guarantee than validating such a parameter would have been.

## 5. Unified submission architecture

### It defines no ownership rule

```
proof of work    MaintenanceVisibility::scopeOwn()    assigned or created by me
support request  WorkSupportVisibility::scopeOwn()    submitted by me
```

Both are **called**. **Verified by search: no `technician_id` comparison exists
anywhere in the `WorkSupport` domain outside `WorkSupportVisibility`.** There is
no third definition of "mine".

### A job is not a submission

Owning a maintenance record is not the same as having submitted proof against
it — an administrator may schedule work a technician has not yet been to. So the
proof-of-work half is **ownership AND a scan this person bound to it**
(`qr_scan_logs.maintenance_record_id`, the DD-50 binding Stage D writes). A
record with no such scan stays on the maintenance queue where it belongs, and a
test asserts it does not appear here.

### Why the union is on keys

The two halves are different shapes and cannot be unioned as rows without
flattening one into the other's columns. The union carries only
`(kind, id, submitted_at)` — enough to order and page correctly **in the
database** — and the page's models are then loaded per kind, two queries, in the
union's order. Merging two already-paginated lists in PHP would have been wrong
at every page boundary. `id` breaks timestamp ties so the ordering is total.

The scopes are applied **again** when the page's models are loaded, so a row that
slipped out of scope between the count and the fetch disappears rather than
renders.

## 6. Frontend

Impeccable's context was loaded this session and its product register followed;
`PRODUCT.md`, `DESIGN.md` and the existing components were inspected before any
component was written. Every control is an existing component on existing
tokens — no new visual vocabulary.

**One nav item, relabelled.** FR-WSR-009 asks for *one* dedicated item covering
both kinds, so "My requests" became "My submissions" rather than gaining a
neighbour. A second item would have contradicted the sentence it was meant to
satisfy.

**The gallery reuses the pattern, not the component.** `RepairEvidenceGallery` is
bound to a maintenance record: it groups by before/during/after, uploads, and
deletes. A support request's evidence has no stages and is immutable once
submitted. So `SupportEvidenceGallery` reuses the established *mechanism*
exactly — bytes through the authenticated client, object URL held and revoked on
unmount, never an `<img src>` at the route — without inheriting three affordances
that would be wrong here. **No second gallery architecture**, and no raw storage
path or direct storage URL anywhere in the client.

**States shipped:** loading (skeletons in the page's own shape), empty (which
teaches the flow rather than saying "nothing here"), error (the server's sentence
relayed), and the **broken-attachment** state — a named "Preview unavailable"
rather than an empty box, so nobody concludes the evidence was never attached.

### Accessibility

Asserted through the accessibility tree, by role and name:

- lightbox opens from the **keyboard** (`Tab` → `Enter`)
- closes on **Escape** and **returns focus** to the trigger
- alt text from the technician's caption, falling back to the filename — never empty
- the `kind` of each entry is carried **as text**, not colour or icon alone
- icon-only controls carry `sr-only` names; `aria-label` on each preview trigger
- 48–60 px targets throughout; responsive from 320 px

**Deferred as instructed:** no axe/WCAG automation and no browser visual
regression. `axe-core` was **not** added and no browser automation was
introduced.

## 8. Two defects found in my own work

### F-1 · A vacuous "unauthenticated" assertion *(found and fixed)*

`WorkSupportAttachmentTest`'s `beforeEach` signs in to create the fixture, and
Laravel's `actingAs` persists for the whole test instance. The first version of
*"it refuses an unauthenticated caller"* therefore ran **as the technician** and
returned 200 — the test was asserting nothing.

Fixed with `$this->app['auth']->forgetGuards()`, after which it correctly
returns 401. **I checked every other suite for the same pattern:** Stage D's and
Stage E's `beforeEach` blocks do not call `actingAs`, so their unauthenticated
assertions were and are genuine. Only this new file was affected.

### F-2 · A too-specific non-disclosure assertion *(found and corrected)*

The first version compared the two 404 bodies byte for byte and failed. On
inspection the only difference was **the uuid the caller had themselves sent**,
echoed back in debug mode — which discloses nothing. The assertion now compares
the failure *mode* and proves neither response names the other request or a
storage path, which is the property that actually matters.
