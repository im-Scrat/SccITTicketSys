## 5. Lifecycle and authorization matrix implemented

### Lifecycle

```
scheduled  ──▶  in_progress  ──▶  completed   (terminal)
     │               │   ▲
     │               ▼   │
     │            on_hold
     ▼               │
cancelled  ◀─────────┘                        (terminal)
```

**Completion gates.** Three, all server-enforced in `MaintenanceLifecycle` — not in a FormRequest — because they are invariants of the record rather than of one HTTP shape. WP-2.6b's scanned submission will meet the same wall without passing through the HTTP layer that exists today.

1. Every **required checklist item** complete (FR-MNT-004).
2. A **resolution recorded — for every maintenance type** (Client decision 1, 2026-08-29). A photograph shows a machine; only the resolution says what was done to it.
3. At least one **repair image** for the maintenance types that require evidence (Client decision 2, 2026-08-29).

**Evidence rule as approved (Client decision 2, 2026-08-29).**

| Maintenance type | Evidence before completion | `is_preventive` |
|---|---|---|
| Corrective | Required | false |
| Hardware upgrade / replacement | Required | false |
| Preventive | Supported, not universally required | true |
| Inspection | Optional | true |
| Cleaning | Optional | true |

The rule is read straight off the existing `maintenance_types.is_preventive` column, which already partitions the seeded catalogue exactly this way. **No schema change, no per-type evidence configuration table and no new column were introduced** — the distinction the rule draws is the distinction the data already carried, and a second place to record it would only be somewhere for the two to disagree. A type added later inherits the rule from its own flag, so an administrator adding "Emergency repair" gets the corrective treatment without remembering a second setting.

**PC-unit effect (FR-MNT-008).** Moving to `in_progress` stores the displaced status and condition on the record and sets the machine to `under_maintenance`. Completing restores the stored status and marks the machine `working`. Cancelling restores both prior values exactly, because a cancelled visit asserts nothing about the machine.

**Terminal states.** `completed` and `cancelled` are both terminal; nothing reopens a completed record. A further visit is a further record.

## 7. Security regression results

`tests/Feature/Security/` — **27 passed, 118 assertions.** Ticket and asset attachment behaviour asserted unchanged.

Nine new maintenance cases prove the Phase 2.6 boundary was **extended, not bypassed**:

1. A client-supplied MIME type is rejected in favour of byte-level detection.
2. SHA-256 checksum, file size and original filename are stored (the DR-021 columns).
3. A real text file declared as `image/png` is rejected — the maintenance profile is narrower than the ticket profile.
4. Markup uploaded as evidence is rejected.
5. A traversal filename never reaches the storage path; the stored path is server-composed.
6. Evidence is served with `nosniff` and `default-src 'none'; sandbox`.
7. A poisoned stored MIME type degrades to `application/octet-stream` on download.
8. A PDF is forced to `Content-Disposition: attachment`.
9. A non-owner is refused the download, and a foreign evidence identifier returns 404.

The profile-parity test now covers all three profiles and asserts that PROFILE_MAINTENANCE excludes `text/plain`, and that no profile may ever admit `text/html`, SVG or XHTML.

## 8. Frontend verification

Six pages behind `RequirePermission` / `RequireRole`. Two navigation items with distinct icons. A Teacher sees neither and receives the Forbidden surface on every maintenance URL.

Controls are server-driven: `available_transitions` and `abilities` are computed by the same policy and lifecycle code that would decide the request, so **no button exists that the API would refuse**. A blocked completion renders disabled with its specific reasons listed rather than being hidden.

Evidence is fetched as blobs with object URLs revoked on unmount, which is what lets the server force `Content-Disposition: attachment` on documents without breaking image previews.

Colour is never the only signal — every status carries its text label, and the overdue and preventive markers carry icons. Filter state lives in the URL so a filtered view survives refresh, bookmarking and sharing.
