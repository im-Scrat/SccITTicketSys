# Stage F — the plan

## A. What exactly is Stage F?

> ## **Stage F — Evidence Retrieval and Unified Submission Tracking**

The stage that closes the two genuine functional gaps left in WP-2.6b's
technician-facing surfaces: **being able to open the evidence** attached to a
work support request, and **one page that tracks everything a technician
submitted**, proof of work as well as support requests.

It is deliberately **not** the release stage and **not** notifications.

## B. Why does Stage F exist?

Two reasons, both concrete:

1. **A decision is being made on evidence nobody can see.** An administrator
   reviewing a request is told "1 attachment" and cannot open it. The
   photograph is the thing that makes "the power supply is burnt out"
   checkable, and FR-WSR-005 exists precisely so the decision is not made on a
   bare notification.
2. **A technician has no single place to see what they submitted.** FR-WSR-009
   names one page for both kinds of submission. Today proof of work is
   invisible after the confirmation screen scrolls away, so a technician cannot
   answer "did my evidence for PC-6739 actually save?" without an administrator.

## J. Security threats Stage F must address

| Threat | Control |
|---|---|
| **IDOR on an attachment** | Resolved **through** the parent request, which is itself scoped by `WorkSupportVisibility`. Another technician's attachment: 403/404, never the bytes. |
| **IDOR on the unified list** | Both halves scoped by their owning service — `WorkSupportVisibility::scopeOwn()` and `MaintenanceVisibility::scopeOwn()`. **No third definition of "mine".** |
| **Forged identifiers** | Attachment uuid must belong to the named request; request uuid must be reachable. Nesting, not trust. |
| **Privilege escalation** | Download reuses the read ability. It grants nothing an administrator does not already have and nothing a technician has beyond their own. |
| **Information leakage** | No storage path in any payload; `Content-Disposition` decided by `AttachmentSecurity`, **never** by the stored string; a type outside the allow-list degrades to an opaque attachment. |
| **Stored-XSS via upload** | PDFs and text are never served inline — the existing `INLINE_SAFE` raster-only list is reused unchanged. |
| **Replay / concurrency** | Not applicable — Stage F writes nothing. Stated rather than assumed. |
| **Unauthorized state transitions** | Not applicable — no transition exists in this stage. |
