### 4.1 Root cause

`frontend/e2e/fixtures/app.ts` provides **8** exports:

```
EMAIL_LABEL  PASSWORD_LABEL  apiFetch  apiStatus  goto  settle  signIn  signOut
```

Its specs import **three symbols that do not exist**:

| Spec | Missing imports |
|---|---|
| `announcements.spec.ts` | `apiJson`, `apiLogin` |
| `notifications.spec.ts` | `apiLogin`, `json` |

The `e2e` project's `testMatch` is
`/specs\/(auth|qr-workflow|notifications|announcements)\.spec\.ts/`, so these two
broken specs take the whole project down with them. `auth.spec.ts` and
`qr-workflow.spec.ts` import only existing symbols and would otherwise load.

### 4.2 This is a recovery artifact, not a regression

| Evidence | Finding |
|---|---|
| File date | `Sep 21 01:38` — the restoration timestamp, untouched since |
| In the 20 formatted files? | **No** — `fixtures/app.ts` was never formatted |
| Source drift check | 21/21 unchanged; this file was not among them |
| Transcript `0c8043a1` line 938 | **`Edit`** on `…/e2e/fixtures/app.ts` adding `apiLogin`, `json` |
| Transcript `0c8043a1` line 988 | **`Edit`** on the same file adding `apiLogin` |
| Transcript `0c8043a1` line 1144 | Content carrying all three: `apiJson`, `apiLogin`, `json` |

The file was **extended by `Edit` operations during WP-2.7b/2.7c**. The
restoration recovered the **pre-edit** version of `fixtures/app.ts` while
recovering the **post-edit** versions of the specs that consume it.

**This is precisely the same failure mode as the Pint drift** — the recovery
reproduced an earlier state of a file whose later modifications were not
captured. It was invisible until the suite was actually run.

### 4.3 Recoverability — Classification B, STRONG RECOVERY

All three missing exports are present verbatim in transcript `0c8043a1`, with
full bodies and signatures:

```ts
export async function apiLogin(page: Page, role: Role): Promise<void> { … }
export async function apiJson<T>(page: Page, path: string, method = 'GET', body?: unknown): P…
export function json<T>(response: { status: number; body: string }): T { … }
```

Classified **B (strong)** rather than A (exact) because they arrive as `Edit`
payloads rather than a single whole-file `Write`. Line 1144 appears to carry the
complete post-edit file and may support an **exact** recovery; that can be
confirmed if repair is authorized.

**No repair was made** — modifying test infrastructure is not authorized.
