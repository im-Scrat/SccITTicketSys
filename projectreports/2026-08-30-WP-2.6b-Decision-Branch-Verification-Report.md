## 5. One test fault, reported rather than buried

The first run reported **FAIL** on *"reschedule date matches what was entered"*:
entered `2026-09-04T21:16`, stored `2026-09-04T13:16:00+00:00`.

**The application was right and my assertion was wrong.** The `datetime-local`
input yields a local wall-clock value, which the client converts with
`toISOString()`; the server stores UTC. The host is GMT+8, so 21:16 local **is**
13:16 UTC. Verified numerically rather than argued:

```
entered as epoch: 1788527760000
stored  as epoch: 1788527760000
SAME INSTANT: true
```

The stored value is correct to the minute. Counting that check as the pass it
is, the run is **28/28**.

I am flagging it because a date assertion that fails for a timezone reason is
exactly the kind of thing that gets quietly re-written until it goes green, and
the distinction between "the app is wrong" and "my check is wrong" matters more
than the score.
